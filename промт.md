# 🧠 DOMAIN DROP CATCHER — АРХИТЕКТУРА ПРОЕКТА

---

# 1. ОБЩАЯ КОНЦЕПЦИЯ

Система предназначена для перехвата освобождающихся доменов (Сразу мы делали именно под Францию, но сейчас делаем мульти проект, под все зоны, так как Gandi например, позволяет регистрировать разные доменные зоны) через API регистраторов (Gandi и др.) с высокой скоростью.

Архитектура строится по принципу:

* CONTROL SERVER (центральный управляющий узел)
* WORKER SERVERS (исполняющие узлы, распределённая нагрузка)

---

# 2. ОБЩАЯ СХЕМА

CONTROL управляет системой. Это будет главный сервер, управляющий остальными. То есть я его буду ставить на отдельный vps сервер, с которого я буду контроллировать workers сервера. Также надо будет сделать систему управления, где я буду добавлять неограниченное количество workers серверов в панель и управлять ими через веб панель. Сразу будет 1 главный(control) сервер и 1 workers сервер, но это только на старте проекта, то есть сейчас, дальше надо будет добавлять workers сервера для наращивания мощности проекта.
WORKERS выполняют регистрацию доменов. Workers это тоже отдельные vps сервера, которые будут крепится к главному control серверу от которого он будет получать команды и состояние worker сервера, пусть это будет загрузка cpu, ram и степень работы в данный момент, то есть столько rps он держит в данный момент

Каждый WORKER:

* работает с одним API. Имеется ввиду с одним api от данного конкретного регистратора, а регистраторов может быть несколько
* имеет свой IP. Каждый имеет свой ип, это потому что сделано для распределения нагрузки и использования разных ип адресов, конкретно сейчас, это условия масштабирования для Gandi
* держит лимит API (например 16 RPS для Gandi). Это максимальное значение для Gandi, но должна быть возможность регулирования rps для каждого конкретного воркер сервера в главное панели на контрол сервере. И в зависимости от подключенных api в данный момент.
